# マイルストーン4: ダッシュボードUIの実装

マイルストーン1のモックアップ（design/mockups/）をベースに、Next.js + Tailwind CSSで実際に動くダッシュボードを実装した。

## 起動方法

```bash
cd hasshin
npm run dev
```

`.env.local` の `ANTHROPIC_API_KEY` を読み込む。ログイン画面で以下の初期アカウントを使用：

- ユーザーID: `editor@kitatama-tobu.example`
- パスワード: `hasshin-demo`

（ローカル開発用の初期値。本番導入時は変更すること。単一アカウントだが `users` テーブル設計は複数アカウントに対応済み。[docs/DATA_MODEL.md](./DATA_MODEL.md) 参照）

## 実装した画面・機能

- ログイン（Cookieセッション、`node:crypto` の scrypt でパスワードハッシュ化）
- レビュー待ち記事一覧（ステータス・地域タグでの絞り込み、公開非推奨バッジ、重複・内部情報アラート表示）
- 記事編集画面：原文/リライト比較、内部情報のハイライト表示（未確認=赤／確認済み・除外済み=緑）、地域タグの手動変更、重複アラートの確認・却下、承認・却下、未確認の内部情報が残っている間はエクスポートをブロック
- PDFアップロード：実際にマイルストーン3のパイプライン（抽出→記事構造化→地域タグ付け→リライト→重複検出）をClaude APIで同期実行し、結果をダッシュボードに反映
- アーカイブ：地域別のサイト掲載件数、承認・エクスポート済み記事の一覧

## データ層について（重要な制約）

**Supabaseにはまだ接続していない。** `src/lib/data/store.ts` に、サーバープロセスのメモリ上にデータを保持するインメモリストアを実装し、Supabaseの代替として使っている。

- 起動時に `prototype/pdf-extraction/output/*.pipeline.json`（マイルストーン2・3で実際にClaude APIを使って処理した3件のPDFの結果）を読み込み、シードデータとする。ダミーデータではなく実際にAI処理された記事が入っている
- PDFアップロード時は、同じパイプラインをその場で実行し、結果をストアに追加する
- **サーバーを再起動するとアップロードした内容は失われる**（インメモリのため）。これは想定された制約で、Supabase接続時に解消される
- `store.ts` がexportする関数（`listArticles`、`updateArticle` 等）のシグネチャは、Supabase接続後もそのまま使える設計にしてある。中身をSQLクエリに差し替えるだけで移行できるはず

## 実装中に見つけて直したバグ

Next.js（Turbopack）はAPIルートとページを別のモジュールインスタンスとして扱うことがあり、通常の `let` によるID採番カウンタだとインスタンスごとにリセットされ、新しくアップロードした記事のIDが既存の記事と衝突する不具合があった（実際に、アップロードした記事の出典ファイル名が別のPDFのものとして表示される形で発覚）。ストア本体と同様に `globalThis` で採番カウンタを共有するよう修正し、実際にPDFをアップロードして正しい紐付けになることを確認済み。

## 検証済みの動作（ブラウザで実機確認）

- ログイン → ダッシュボード表示（実データ、7〜10件のレビュー待ち記事）
- 記事編集画面での内部情報ハイライト表示、地域タグ変更、承認
- 承認後のエクスポート（HTML/Markdown/プレーンテキスト、`/api/export/[id]` で未確認の内部情報が残っていればブロック）
- 却下
- 実際のPDF（`推進ニュース2026.07.31.pdf`、未処理だったサンプル）をアップロードAPI経由で処理し、新しい記事3件が正しくダッシュボードに反映されることを確認（約2分で処理完了。3件とも党員拡大・党費納入督促などの内部限定内容で、正しく「公開非推奨」判定）
